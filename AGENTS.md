# Instructions for coding agents

## Commands
Node 22+ and [go-task](https://taskfile.dev) (preinstalled here). No dependencies to install: the site is
plain HTML/CSS and `scripts/check.mjs` uses only Node's standard library. Every command is non-interactive.

| What | Command |
|---|---|
| Install | none — no dependencies (Node 22+, `task`) |
| **Check (must pass before you finish)** | `task check` = `node scripts/check.mjs` |
| Run locally | `task serve` (python3, http://localhost:8912) |
| Live reload | `task dev` (needs `npm i -g live-server`) |
| After editing `styles.css` / `ogimage.jpg` | `task cache-bust` (rewrites the `?v=` hash in both pages) |
| Regenerate the social image | `task generate:og-image` (macOS only: Chrome + `sips`) |
| Deploy | `task deploy:prod` = `wrangler pages deploy . --project-name worotyns` (needs `wrangler`) |

`task check` fails on: a missing local link or asset, an external link without `target="_blank"` +
`noopener`, a page without exactly one `<h1>`, unbalanced `<main>/<p>/<dl>/<div>`, or a stale `?v=` hash.
A stale hash is fixed with `task cache-bust`, never by hand. HTML comments are ignored.

## Map of the repo
| Path | What |
|---|---|
| `index.html` | the whole landing page: `whoami`, `ls ~/projects`, `contact` |
| `404.html` | Cloudflare Pages 404 page; one link home |
| `styles.css` | the single stylesheet; content-addressed from the HTML as `/styles.css?v=<sha1[0:8]>` |
| `scripts/check.mjs` | dependency-free checker behind `task check` |
| `Taskfile.yml` | canonical commands (`check`, `serve`, `dev`, `cache-bust`, `generate:og-image`, `deploy:prod`) |
| `_redirects`, `_headers` | Cloudflare Pages: 301s for old URLs, security/cache headers (styles are cached forever) |
| `robots.txt`, `sitemap.xml` | indexing; `sitemap.xml` needs a new `<lastmod>` when the page changes |
| `site.webmanifest`, `favicon.*`, `apple-touch-icon.png`, `android-chrome-*.png` | icons and manifest |
| `ogimage.jpg` | social preview, generated by `task generate:og-image` |
| `.github/` | agent issue template, PR template, release workflow (tag + Pages deploy on merge to main) |
| `.herdr-projects.json` | board config: the check command the agent workflow runs |

## Definition of Done
1. Every acceptance criterion of the issue has a test, or a stated manual proof in the PR description
   (for this repo: the `task check` output, plus what you looked at if the change is visual).
2. `task check` passes locally.
3. The PR description lists the acceptance criteria, ticked, each with how it was verified.
4. The diff stays inside the issue's scope. Anything else you noticed goes under "Also noticed" in the PR, not in code.
5. No secrets, no generated files, no unrelated formatting changes.
6. If the issue is unclear, ask instead of guessing:
   `herdr-projects report --state blocked --kind question --msg "<question>"`.

## Conventions
- Plain static HTML/CSS, no build step and no dependencies. Keep it that way; a new tool needs a reason in the issue.
- Commit and PR titles follow `git log`: `type(scope): imperative summary` (`feat(site):`, `fix:`, `chore:`), lowercase after the colon.
- The terminal copy is lowercase (`whoami`, `ls ~/projects`, `cd ~`), and each page has exactly one `<h1>`.
- External links get `target="_blank"` and `rel="noopener"`; internal links stay in the same tab.
- Touching `styles.css` or `ogimage.jpg` means running `task cache-bust` and committing the new `?v=` in `index.html` and `404.html`.
- A new page or a moved URL means updating `sitemap.xml` and adding a 301 in `_redirects`; old pages are never deleted silently.
- The deploy root is the repo root (Cloudflare Pages project `worotyns`). No build output, no `dist/`.
